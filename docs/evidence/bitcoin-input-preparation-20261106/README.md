# Wallet-owned Bitcoin input preparation

The dedicated prepare/get/sign/cancel/broadcast APIs reuse the existing Native Bitcoin self-recovery records, signer, owned-input/Stock qualification, one-use durable attempts, exact signature verifier, encrypted backup and snapshot lifecycle. Only the explicit new purpose allows2–8wallet-created ordinary Bitcoin outputs plus change. Caller input is a strict version1 REGTEST budget, stable operation UUID, canonical integer output amounts, fee rate, miner ceiling, at-most120second initial signing deadline and bounded exclusions. Native BDK owns selection, scripts and change; every selected input must be currently confirmed/mature, ordinarily spendable and free of RGB assignments/other holds. No user destination, new crypto, market authority, Stock reconstruction or settlement engine.

Unsigned original and Native holds persist before prepare ACK. The same operation id with identical terms reads/flushes the retained original; changed terms refuse. Native signing persists one attempt before BDK. Only the same signed original can broadcast once under separate fresh bounded broadcast approval. Signed, attempted, restored, cancelled or changed originals refuse unsafe dispatch. An explicit cancellation releases ONLY a proven unattempted, unsigned, unrestored preparation after durable flush, retaining its original record. A failed cancellation flush restores its prior in-memory flag, including an already-cancelled idempotent retry. Expiry alone never cancels or releases anything.

BDK builder derivation metadata is deliberately omitted before retention, using the existing minimal witness-only PSBT model. The standard builder still constructs all transaction terms; the established descriptor signer and exact BIP341 verifier remain unchanged. The parser requires precisely this minimal metadata, version2, exact targets/values/change, checked actual fee within the approved cap and no nonbinding sighash override. Default ordinary Bitcoin send remains at its previous output limit; legacy one-output self-recovery purpose/JSON is unchanged. Old serialization omits new None/false fields; new managed state refuses old-reader downgrade rather than losing holds.
